# WebFlash — 网页版写频 / 刷字库工具

一个单文件网页工具（Web Serial），用来读写 UV-K1 / UV-K5 V3（F4HWN 固件）的
**信道**，以及刷入**中文点阵字库**。不依赖任何服务器、不加载任何外部资源，
浏览器里跑，数据全在本机。

## 打开方式

1. 用 **Chrome 或 Edge**（需要 Web Serial）。
2. 直接双击 `index.html` 即可（`file://` 通常可用，脚本都是普通 `<script>`，不是 module）。
3. 若浏览器因安全策略拦住，在本目录执行：

   ```sh
   python -m http.server 8000
   ```

   然后访问 <http://localhost:8000/>。

## 用法

### 信道

1. 点 **连接电台** → 选串口。UART 桥用 38400（下拉框默认），USB CDC 选“不设置”。
   连上后状态栏会显示固件版本。
2. 点 **读取电台**（读 1024 条信道，约十几秒）。
3. 改名称 / 频率 / 亚音 / 功率 / 带宽 / 扫描列表等；点行尾的 `▸` 展开更多选项
   （发射锁、繁忙禁发、收发倒置、DTMF、PTT ID、压扩、步进、频段、清空信道）。
4. 点 **写回改动**：**只有改过的信道会被写入**，没动过的字节不会被碰。
5. 点 **重启电台** 让新信道生效（电台不会自动重读信道表）。

补充：

- **名称**是 UTF-8，最多 15 字节（一个汉字 3 字节）。工具按字符边界截断，
  不会写入半个汉字；中文名也可以直接在电台上用拼音输入。
- **频率**填 `145.50000`（MHz，带小数点）或 `145500`（kHz，不带小数点）。
- **备份**：读取之后用 **导出 JSON** 存一份；**导入 JSON** 会把数据放进编辑区，
  确认后再写回。
- **新增信道** 会找一个空槽；填入频率后，频段（影响发射功率校准）会自动跟着频率走，
  手动改过就不再覆盖。
- **亚音** 下拉里 CTCSS/DCS 的编号直接取自固件的 `dcs.c` 表，所以写入的下标就是机器认识的下标。

### 字库

- **刷新字库状态**：走 `0x0740`，显示电台里字库是否存在、版本、期望尺寸。
- 选本地 `cn_font.bin`（205367 字节，参考实现在 `Dondji/docs/font/cn_font.bin`），
  工具会先校验尺寸、版本字节、首字形探测值和索引表是否指向汉字，不匹配不写。
- **刷入字库** 逐包写入（128 字节/包）并可回读校验；中途断掉不会留下半份字库——
  版本字节是整份文件的最后一字节，只有整份写完电台才认它。
- 每一条命令都带超时和重试（USB CDC 偶发丢包时能自动恢复，不会卡住）；
  如果字库写入中途失败，日志里会给出已写入的字节数，**再点一次“刷入字库”会从断点继续**，
  不用重写 205 KB。
- 只支持带 `ENABLE_CHINESE` 的固件；否则字库命令不存在，会提示无响应。

## 它写哪些区域，不写哪些

| 区域 | 地址 | 是否写入 |
|---|---|---|
| 信道记录（频率/亚音/功率/带宽/步进等） | `0x0000 .. 0x3FFF` | ✅ |
| 信道名（16 字节/条，UTF-8 15 字节） | `0x004000 .. 0x007FFF` | ✅ |
| 信道属性（频段/压扩/排除/扫描列表） | `0x008000 .. 0x087F` | ✅ |
| 中文点阵字库 | `0x1AD000` 起 205367 字节（止于 `0x1DF237`） | ✅ |
| 校准数据 | `0x010000` 起 | ❌ 绝不触碰 |
| 设置区（`0x00A000` 起）、VFO/频率信道（`0x009000`） | | ❌ 不写入（只读工具不涉及） |
| 多启动固件槽位 / 状态标记 | `0x020000+`、`0x100000+` | ❌ 绝不触碰 |
| overlay apps 槽位（Labs） | `0x102000 .. 0x122000` | ❌ 绝不触碰 |
| 语音资源 / RX-TX 日志 | `0x14C000+`、`0x1E0000` | ❌ 绝不触碰 |

两点要注意：

- 写入的是**当前生效的那个配置库**。用多启动切换过配置库时，先确认电台当前用的是哪一个。
- 固件只有收到 `0x051D` 的整 8 字节组写入时才落盘（`App/app/uart.c` 里
  `size / 8` 的循环），所以 2 字节的属性区是按“所在 8 字节组读-改-写”处理的，
  不会碰坏同组里其他三条信道。

## 用的命令

| 命令 | 用途 |
|---|---|
| `0x0514` | 握手，锁定本次会话的时间戳（后续读写都要带） |
| `0x051B` | 读 EEPROM/外部 Flash（≤128 字节/次） |
| `0x051D` | 写（整 8 字节组） |
| `0x05DD` | 重启电台 |
| `0x0740` / `0x0742` / `0x0744` | 字库信息 / 写入 / 回读（仅 `ENABLE_CHINESE` 固件） |

帧格式、混淆表和 CRC-16/CCITT 与固件一致，见 `js/webflash.js` 顶部注释与
`App/app/uart.c`。

## 目录

```
index.html            单文件页面（HTML/CSS/内联 UI 脚本）
js/webflash.js        协议 + 信道编解码 + 字库传输（普通脚本，暴露 globalThis.WebFlash）
js/tables.js          由 gen_tables.py 从固件 C 源码生成的常量表
gen_tables.py         表生成器（改固件里的表之后要重跑）
host_tests/test_webflash.mjs   主机端测试（node 运行）
```

`js/tables.js` 里的东西**不要手改**：CTCSS 50 个频点、DCS 104 个码、功率/调制/步进标签、
扫描列表数量、以及各区域基址和字库常量全部从 C 源码解析而来，并且生成器会
按 `CMakePresets.json` 里 `default` preset 的开关处理 `#ifdef`
（例如 `ENABLE_BYP_RAW_DEMODULATORS` 关闭时，调制下拉里就不会出现 BYP/RAW）。

```sh
python tools/webflash/gen_tables.py        # 改完固件里的表后重新生成
node tools/webflash/host_tests/test_webflash.mjs   # 跑测试
```

## 测试覆盖

`host_tests/test_webflash.mjs` 用一个**照着 `App/app/uart.c` 写的电台模拟器**
（帧解析、应答组装、`0x0514/051B/051D/074x` 处理、以及“只存整 8 字节组”的规则）
驱动真实的 `js/webflash.js`，检查：

- 帧格式与固件解析器一致，握手/读/写/字库全流程；
- 会话时间戳不匹配会被拒绝；未对齐写入在发出前就被拦下；
- 信道记录、属性、名称编解码的**手算黄金向量**，UTF-8 边界截断、损坏序列；
- 整片读写流程：读回 → 编辑 → 只写改动 → 属性组写入不碰邻居 → 清空后是全新槽；
- 字库：校验接受/拒绝各种损坏文件、上传字节完全一致、回读校验、**中断上传不会被视为有效字库**；
- `js/tables.js` 与固件源码同步（表过期会失败）；
- 页面本身：内联脚本能编译、脚本用到的每个元素 id 都存在、没有用 module 脚本
  （否则 `file://` 会被 CORS 拦住）。

## 注意事项

- 电台要**开机运行固件**、不在 bootloader、不锁屏，并且串口没被其他写频软件占用
  （先关掉 CHIRP / UV Studio）。
- 本工具不做整片 flash 刷写、不做校准恢复，也不碰多启动槽位。
- 如果用 CHIRP 写频：它的名字字段是老式 10 字符 ASCII 模型，整机上传有可能把中文名
  截断或清掉，用之前先备份。
